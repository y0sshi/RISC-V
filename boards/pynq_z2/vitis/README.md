# PYNQ-Z2 real-HW bring-up (Vitis / boot side)

Offline (no-board) preparation for booting the RISC-V SoC bitstream on real
PYNQ-Z2 hardware. The Vivado bitstream side is in `../vivado/`; this directory
holds the PS-side boot artifacts (XSA -> FSBL -> BOOT.bin) and the JTAG
bring-up script. Structurally identical to `boards/zybo_z720/vitis/` (same
chip, same PS7 flow) -- only paths, the UART pin/wiring, and the platform
name differ.

All Xilinx tools must run from **PowerShell**, not Bash/MSYS (its path translation
crashes Vivado synth and the Vitis server). Find the tools via `$env:XILINX_VIVADO` /
`$env:XILINX_VITIS` (or PATH after `settings64.bat`); examples below run from the repo
root, where `$PWD\...` gives Vivado the absolute `-source` path it needs.

**One-shot (cross-platform):** `python boards/pynq_z2/build_all.py` (Windows or Linux,
stdlib only) runs `bit -> fsbl -> bootbin` (use `--stage xsa fsbl bootbin` to reuse an
existing impl). Retarget the PL clock first with `python ..\set_pl_freq.py <MHz>`. The
bash/docker side (firmware, sim, tests) is the top-level `make` -- run `make help` at the repo root.

## Clock / UART facts baked into the design (read first)

- PL clock `FCLK_CLK0` = **50 MHz** (`build_pynq_z2.tcl` `PL_FREQMHZ=50`), same
  target already validated on Zybo Z7-20 (same chip, same RTL; `docs/freq_50mhz.md`).
- `rv_soc` `MTIME_DIV=1` => CLINT `mtime` ticks at **50 MHz** on hardware.
- The 16550 bit period is `divisor*16` PL clocks; the 8250 driver programs
  `divisor = clock-frequency/(16*baud)`, so `actual_baud = PL/(divisor*16)`.

Therefore the **real-HW device tree** (`docs/opensbi/rv_soc_hw.dts`,
`tests/linux/rv_soc_linux_hw.dts`) must carry the timebase-frequency / serial
clock-frequency / current-speed matching this board's realized PL clock -- these
are the SAME shared DTS files used by Zybo (`set_pl_freq.py` rewrites them for
whichever board was last retargeted), so **re-run `set_pl_freq.py` and rebuild
firmware if you switch boards** or change frequency.

Use a **57600 8N1** terminal on hardware (matches the Zybo 50 MHz baud choice;
`set_pl_freq.py --baud` can pick another).

## prep-A/B/C (done offline)

- **prep-A** real-HW DTS: `docs/opensbi/rv_soc_hw.dts`, `tests/linux/rv_soc_linux_hw.dts`
  (shared across boards; re-run `set_pl_freq.py` before building firmware for this board).
- **prep-B** export XSA from the built impl (no re-impl):
  ```
  & "$env:XILINX_VIVADO\bin\vivado.bat" -mode batch `
      -source $PWD\boards\pynq_z2\vivado\export_xsa.tcl `
      *> $PWD\boards\pynq_z2\vivado\export_xsa.log 2>&1
  ```
  -> `../vivado/rv_riscv_pynq_z2/rv_riscv_pynq_z2.xsa` (ps7_init + bitstream). The full
  `build_pynq_z2.tcl bit` flow now also emits the XSA automatically.
- **prep-C** FSBL + BOOT.bin:
  ```
  & "$env:XILINX_VITIS\bin\vitis.bat" -s `
      $PWD\boards\pynq_z2\vitis\fsbl.py *> $PWD\boards\pynq_z2\vitis\fsbl.log 2>&1
  python make_bootbin.py --firmware <fw_payload_hw.bin>
  ```
  - FSBL is auto-generated by the standalone platform build ->
    `ws/pynq_z2_plat/export/pynq_z2_plat/sw/boot/fsbl.elf` (32-bit ARM, ps7_init).
  - `make_bootbin.py` writes `boot.gen.bif` (firmware **before** bitstream, raw
    `.bin` with `[load=0x00200000]` and no exec addr) and runs bootgen. Layout
    verified on Zybo: FSBL(exec OCM) -> firmware@0x200000 (data, no A9 handoff)
    -> bitstream last, so the RISC-V core leaves reset with firmware already
    resident in DDR.

## prep-D/E -- ready for the board

- **prep-E** firmware: rebuild OpenSBI/Linux fw_payload against the current DTS
  (matching this board's realized PL clock), entry 0x200000. Rebuild recipe
  (mirrors Zybo; see `boards/zybo_z720/vitis/README.md` prep-E for the full
  docker command):
  ```
  docker run --rm -v "E:/work/git/RISC-V.git:/workspace" -w /workspace/tests/opensbi \
    riscof_run:latest bash -c \
    "FW_BASE=0x00200000 DTS=/workspace/docs/opensbi/rv_soc_hw.dts OUT=fw_payload_hw bash build.sh"
  cp tests/opensbi/work/opensbi/build/platform/generic/firmware/fw_payload.elf \
     tests/opensbi/work/fw_payload_hw.elf
  python make_bootbin.py --firmware ...\fw_payload_hw.bin
  ```
  Linux later: `tests/linux/build.sh` with `DTS=.../rv_soc_linux_hw.dts
  OUT=fw_payload_linux_hw` (CRLF-strip per CLAUDE.md); swap the elf in
  `bringup_jtag.tcl`.
- **prep-D** JTAG bring-up script `bringup_jtag.tcl` (XSDB debug flow, which IS
  available here -- only the classic IDE project flow is not). It `connect`s,
  selects the A9, runs `ps7_init`/`ps7_post_config`, `dow`s the firmware ELF to
  0x200000, then `fpga`-configures the PL so the RISC-V core boots from 0x200000.
  `ps7_init.tcl` is extracted from the XSA (gitignored; re-extract with
  `python -c "import zipfile; open('ps7_init.tcl','wb').write(zipfile.ZipFile(r'../vivado/rv_riscv_pynq_z2/rv_riscv_pynq_z2.xsa').read('ps7_init.tcl'))"`).

## On the board (P1 -- run these)

1. Power the PYNQ-Z2, set JTAG boot mode (or insert the SD with `BOOT.bin` for SD boot).
2. Wire a 3.3 V USB-UART to **Pmod JB**: FPGA TX=**W14** -> adapter RX,
   FPGA RX=**Y14** <- adapter TX, common GND. Open the terminal at **57600 8N1**.
3. JTAG path (recommended):
   ```
   & "$env:XILINX_VITIS\bin\xsct.bat" `
       $PWD\boards\pynq_z2\vitis\bringup_jtag.tcl
   ```
   Expect the OpenSBI banner + `PAYLOAD: hello` on the UART.
4. SD path (alternative): copy `BOOT.bin` to a FAT32 SD card, set SD boot mode,
   power-cycle.
